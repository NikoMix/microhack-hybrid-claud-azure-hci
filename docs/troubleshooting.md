# Troubleshooting

Use this guide during delivery to diagnose common failures. Commands assume the
pupil is in GitHub Codespaces using Bash and Azure CLI.

> [!TIP]
> First confirm the active subscription. Many lab issues are caused by deploying
> into the wrong tenant or subscription.

```bash
az account show --query '{name:name,id:id,tenant:tenantId,user:user.name}' -o table
echo "ARM_SUBSCRIPTION_ID=$ARM_SUBSCRIPTION_ID"
```

## Challenge 00 — Codespace and setup

### Codespace will not build

Symptoms: post-create script fails, tools are missing, or extensions do not load.

Diagnostics:

```bash
cat .devcontainer/devcontainer.json
bash .devcontainer/post-create.sh
az version --output table || true
terraform version || true
task --version || true
```

Fixes:

- Rebuild the Codespace from the GitHub Codespaces command palette.
- Rerun `bash .devcontainer/post-create.sh`.
- If one best-effort tool install failed, continue if the current challenge does not need it.
- For markdown or validation work, run `task setup` after the post-create rerun.

### `az login --use-device-code` issues

Symptoms: device code expires, wrong tenant, browser blocks login, subscription missing.

Diagnostics:

```bash
az logout
az login --use-device-code
az account list --query '[].{Name:name,Id:id,Tenant:tenantId,Default:isDefault}' -o table
az account set --subscription "<subscription-id>"
az account show -o table
```

Fixes:

- Use an in-private browser window for the device code.
- Confirm the account is invited to the tenant.
- If multiple tenants exist, use the subscription ID, not the display name.
- Export Terraform subscription context:

  ```bash
  export ARM_SUBSCRIPTION_ID="<subscription-id>"
  ```

### Resource provider not registered

Symptoms: deployment fails with `MissingSubscriptionRegistration`.

Diagnostics:

```bash
az provider show --namespace Microsoft.HybridCompute --query registrationState -o tsv
az provider show --namespace Microsoft.KubernetesConfiguration --query registrationState -o tsv
az provider show --namespace Microsoft.RecoveryServices --query registrationState -o tsv
```

Fix:

```bash
for provider in \
  Microsoft.Compute \
  Microsoft.Network \
  Microsoft.ManagedIdentity \
  Microsoft.OperationalInsights \
  Microsoft.Insights \
  Microsoft.HybridCompute \
  Microsoft.GuestConfiguration \
  Microsoft.Kubernetes \
  Microsoft.KubernetesConfiguration \
  Microsoft.ContainerService \
  Microsoft.RecoveryServices \
  Microsoft.DataProtection \
  Microsoft.Security; do
  az provider register --namespace "$provider"
done
```

### Terraform authentication or `ARM_SUBSCRIPTION_ID`

Symptoms: Terraform targets the wrong subscription or reports no subscription found.

Diagnostics:

```bash
az account show --query id -o tsv
echo "$ARM_SUBSCRIPTION_ID"
printenv | grep '^ARM_' || true
```

Fix:

```bash
export ARM_SUBSCRIPTION_ID="$(az account show --query id -o tsv)"
export ARM_USE_CLI=true
terraform -chdir=infra/terraform/base init
terraform -chdir=infra/terraform/base validate
```

### Azure Verified Module download or version errors

Symptoms: `terraform init` fails on module download or provider version solving.

Diagnostics:

```bash
terraform -chdir=infra/terraform/base version
terraform -chdir=infra/terraform/base init -upgrade
terraform -chdir=infra/terraform/base providers
```

Fixes:

- Retry `terraform init`; registry failures are often transient.
- Ensure the Codespace has outbound access to the Terraform Registry and GitHub.
- Do not edit module versions during class unless the trainer has validated the change.

## Challenge 01 — Arc foundations

### Arc onboarding fails for an Azure VM simulation

Azure Arc-enabled servers are intended for machines outside Azure. In this lab,
an Azure VM may stand in for an on-prem server. The challenge may require an
IMDS-block technique so the Connected Machine agent does not detect Azure VM
metadata.

Diagnostics on the VM:

```bash
curl -H Metadata:true --connect-timeout 2 \
  "http://169.254.169.254/metadata/instance?api-version=2021-02-01" || true
sudo azcmagent check --location swedencentral || true
sudo azcmagent show || true
```

Typical Linux IMDS-block command:

```bash
sudo ip route add blackhole 169.254.169.254/32 || true
ip route get 169.254.169.254 || true
```

After blocking IMDS, retry the onboarding command generated by Azure Arc or the
challenge script.

If you need to remove a failed connection:

```bash
sudo azcmagent disconnect --force-local-only || true
az connectedmachine delete \
  --name "<arc-machine-name>" \
  --resource-group "rg-mhb-<initials>" \
  --yes || true
```

### Connected Machine agent status unclear

Diagnostics:

```bash
az connectedmachine list --resource-group "rg-mhb-<initials>" -o table
az connectedmachine show \
  --name "<arc-machine-name>" \
  --resource-group "rg-mhb-<initials>" \
  --query '{status:status,agentVersion:agentVersion,location:location}' \
```

## Challenge 02 — Observability and lifecycle

### No logs or heartbeat in Log Analytics

Diagnostics:

```bash
az monitor log-analytics workspace list \
  --resource-group "rg-mhb-<initials>" \
  -o table

az monitor log-analytics query \
  --workspace "<workspace-id>" \
  --analytics-query "Heartbeat | take 5" \
  -o table
```

Fixes:

- Wait 5-15 minutes for first signals.
- Confirm the Arc resource has the right extension or data collection rule association for the challenge.
- Confirm outbound connectivity from the VM.

### Azure Update Manager assessment missing

Diagnostics:

```bash
az connectedmachine extension list \
  --machine-name "<arc-machine-name>" \
  --resource-group "rg-mhb-<initials>" \
  -o table
```

Fixes:

- Wait for assessment completion.
- Confirm the Arc machine is online.
- Re-run the assessment from Azure Update Manager if the portal allows.

## Challenge 03 — Resiliency

### Quota or regional capacity error

Diagnostics:

```bash
az vm list-usage --location swedencentral -o table
az vm list-skus --location swedencentral --size Standard_B2s --all -o table
```

Fixes:

- Switch to a trainer-approved alternate region.
- Use a similar small B-series VM size if allowed.
- Use trainer demo mode if corporate policy blocks public IPs or VM creation.

### Defender onboarding lag

Diagnostics:

```bash
az security pricing list -o table
az security pricing show --name VirtualMachines -o json
az security assessment list --query '[0:5].{name:name,status:status.code}' -o table
```

Fixes:

- Wait 15-30 minutes; Defender recommendations are not instant.
- Confirm Defender for Servers Plan 2 is intentionally enabled only for the lab window or trial.
- Use portal screenshots from the trainer demo subscription if tenant policy blocks plan changes.

### Backup or Recovery Services vault cannot delete

Diagnostics:

```bash
az backup vault list --resource-group "rg-mhb-<initials>" -o table
az backup item list \
  --resource-group "rg-mhb-<initials>" \
  --vault-name "<vault-name>" \
  --backup-management-type AzureIaasVM \
  --workload-type VM \
  -o table
```

Fixes are in [teardown](teardown.md) because soft-delete and protected items must
be handled carefully.

## Challenge 04 — AKS enabled by Azure Arc

### Connected cluster does not appear

Diagnostics:

```bash
kubectl cluster-info
kubectl get nodes -o wide
az connectedk8s list --resource-group "rg-mhb-<initials>" -o table
az extension list --query "[?name=='connectedk8s' || name=='k8s-configuration'].{Name:name,Version:version}" -o table
```

Fixes:

```bash
az extension add --name connectedk8s --upgrade
az extension add --name k8s-configuration --upgrade
az connectedk8s connect \
  --name "k8s-mhb-<initials>-04" \
  --resource-group "rg-mhb-<initials>" \
  --location swedencentral
```

### Flux GitOps not reconciling

Diagnostics:

```bash
flux check || true
kubectl get pods -A | grep -i flux || true
az k8s-configuration flux list \
  --cluster-name "k8s-mhb-<initials>-04" \
  --cluster-type connectedClusters \
  --resource-group "rg-mhb-<initials>" \
  -o table
```

Fixes:

- Confirm the cluster can reach GitHub and container registries.
- Confirm the repo URL and branch used by Flux exist.
- Delete and recreate the Flux configuration if the source is wrong.

## Challenge 06 — Copilot, agents, skills, and MCP

### MCP server does not appear in Copilot

Diagnostics:

```bash
cat .vscode/mcp.json || true
gh auth status || true
az account show -o table || true
```

Fixes:

- Reload the Codespace window.
- Confirm Copilot Chat is signed in and enabled.
- Confirm the Azure and GitHub MCP server definitions exist in `.vscode/mcp.json`.
- Continue with Copilot Chat over repository context if MCP cannot be restored during the capstone.

### Custom agent not visible

Diagnostics:

```bash
find .github -maxdepth 3 -type f | sort
```

Fixes:

- Reload the Codespace window.
- Confirm the repo contains `.github/agents/*.agent.md` and `.github/skills/`.
- Use the default Copilot Chat participant as fallback and paste only non-sensitive evidence summaries.
